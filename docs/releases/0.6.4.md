# Godot MCP 0.6.4

Fixes a Windows global-install startup failure reproduced with the published 0.6.3 package. npm could leave invalid Zod, ws and MCP SDK dependencies, causing the server to exit before MCP initialize and preventing Codex from opening a chat with a required server.

- The public artifact now bundles its complete production runtime, including SDK core/server, Zod, ws and smol-toml.
- Global installation and reinstallation no longer depend on workspace-hoisted runtime packages.
- Project-local profiles, backups and independent shared project sessions are retained.
- The protocol remains 1 and the tool catalog remains 194 tools.

## Update

```powershell
npm install -g @srdarkx/godot-mcp@0.6.4
```

From each Godot project folder, preview and apply its addon/client migration:

```powershell
npx --yes @srdarkx/godot-mcp@0.6.4 upgrade . --dry-run
npx --yes @srdarkx/godot-mcp@0.6.4 upgrade .
```

Review active-session shutdown and launcher replacement before confirming. Backups and project isolation are retained. Reload an already-open Godot addon and reconnect the client after upgrading that project.

Existing client entries pinned to 0.6.3 do not automatically become 0.6.4 when the global CLI is updated. Upgrade each project explicitly. Source/custom launchers still require explicit replacement consent.

Node.js 22 or newer is required. Project maintenance remains Windows-only; the package is compatible with the existing protocol 1 addon workflow. An active older server may require one controlled restart during its project upgrade.
