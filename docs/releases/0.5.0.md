# Godot MCP v0.5.0 — Geometry and Capture Reliability

Version 0.5.0 adds two MCP tools, bringing the public catalog to 194 tools across eight profiles. The verified runtime target is Windows with Godot 4.6.3.

## New behavior

- `geometry.validate_walkways` checks declared `Line2D` or `Polygon2D` walkway footprints against declared `CollisionShape2D` and `CollisionPolygon2D` nodes in scene-global coordinates. It reports overlap, endpoint connection gaps, unsupported shapes, approximations and whether the result is complete. The tool is read-only; it does not save the scene. TileMap and dynamic physics obstacles are outside this first contract.
- `visual.resolve_capture` accepts a self-contained capture reference and verifies the retained manifest, PNG file and SHA-256 after a session ends. Capture results now include the reference and an absolute path.
- `visual.capture_game` accepts optional `framing.center` and `framing.zoom`. A temporary runtime `Camera2D` captures a close-up and restores the previous camera, including on capture failure, without changing the saved scene.
- `project.events` long-poll waits no longer hold the shared operation gate, so edits and shutdown can proceed while a subscription waits.
- `PROJECT_BUSY` reports known lease-owner operation, process ID and elapsed time. Short addon maintenance retries within a fixed deadline; access denial is a distinct error.
- Scene batch type errors include expected and received types and a valid typed `PackedVector2Array` example for polygon points.

## Guarantees and compatibility

File transactions use a journal, preconditions and compensation around sequential writes. Other processes can observe intermediate files, and unsuccessful compensation requires recovery. The public guides now describe this explicitly. Linux and macOS currently return `UNSUPPORTED_PLATFORM` at project lease initialization; no cross-platform runtime claim is made.

## Verification

The regular Windows CI runs Node 22/24 checks and live Godot integration, including geometry. Its Node 22 lane also runs graphical editor capture and runtime capture; neither can silently skip missing prerequisites. The dedicated self-hosted graphical workflow remains available for diagnosis. The release additionally requires DAP/headless checks, package distribution smoke test and npm publish dry run. A graphical failure is a release blocker. See the validation record in the final release notes for the exact runs.
