# Godot MCP 0.6.3

Codex can discover tools and open multiple chats for the same Godot project without competing server processes. Each client keeps its own connection, tool profile and approvals while sharing the project's editor and runtime session.

- Closing one client leaves the others connected; closing the last finishes the session cleanly.
- CLI and MCP update notices include the commands for upgrading npm and each project.
- Godot projects without Git can register `project.godot` as a Codex root marker with a configuration backup.
- Doctor checks the actual Codex project selection, every bundled addon file and all project configuration fields.
- Windows CRLF migration, linked entry paths, stale descriptors and fixed-port collisions are handled.

## Update a project

From the Godot project folder:

```powershell
npx --yes @srdarkx/godot-mcp@0.6.3 upgrade . --dry-run
npx --yes @srdarkx/godot-mcp@0.6.3 upgrade .
```

The upgrade previews launcher and session changes, retains a backup and confirms shutdown before replacing an active older server. Reload the addon in an already-open Godot editor and reconnect Codex after the upgrade.

For a global CLI installation, update npm first and then upgrade each project:

```powershell
npm install -g @srdarkx/godot-mcp@0.6.3
godot-mcp upgrade .
```

## Notes

Versions 0.6.2 and earlier need this initial upgrade before they can provide future update notices. An older running server needs one restart to load shared connections. Source or custom launchers still require explicit consent before being replaced by the npm launcher. Project maintenance remains Windows-only, and the 194-tool catalog is unchanged.
